# Car Porter — US auction → Bulgaria import evaluator

- **Status:** In progress (Phases 0–4 complete)
- **Created:** 2026-09-16
- **Last updated:** 2026-09-16
- **Owner:** mivebe

## Goal
A personal, locally-run tool that finds cars on Copart and IAAI, works out what a
given lot will really sell for (from past bidfax auctions), checks that exact
vehicle's auction history, calculates the full landed cost in Bulgaria, compares it
with Bulgarian market prices, and gives a **Worth it / Borderline / Not worth**
verdict.

**Success criteria**
- From filters (make, model, year from/to) I get a combined Copart + IAAI lot list.
- Clicking a lot opens a detail panel where, via buttons, I can:
  - get a bidfax price estimate (list of matches with direct links + prices, average),
  - see prior auctions of this VIN / lot number (with VIN paste override),
  - see a landed-cost breakdown in EUR,
  - see BG market listings grouped by marketplace with an average,
  - see a verdict based on profit margin.
- Every feature has passing automated tests before it is marked done.

## Context
- Repo `car-porter` is empty at plan creation (only `.git`).
- Data sources do not allow browser cross-origin requests and several use bot
  protection (Cloudflare / Incapsula), so a pure frontend is impossible; a **local
  backend** does all fetching/scraping.
- Personal use only, runs on the owner's Windows PC. Scraping auction sites may
  violate their ToS — keep request volume low, cache aggressively, never
  redistribute data.
- Owner has a **Copart** member account; **no IAAI** account.
- Bulgaria uses EUR (euro adopted 2026-01-01), so all final figures are in EUR.

## Scope
- **In**
  1. Search filters: manufacturer, model, yearFrom, yearTo.
  2. Search + load lots from Copart and IAAI, merged list.
  3. Lot click → detail panel with manual action buttons (2nd-level search on the lot).
  4. Bidfax price estimate for the lot.
  5. Vehicle auction history by VIN and lot number (auction-history sites) + VIN paste.
  6. Landed cost calculator.
  7. BG market comparison (mobile.bg, cars.bg; autoscout24 + OLX.bg toggles).
  9. Worth / not verdict.
  - Tracking list (saved lots with their estimates), settings page, EN/BG i18n,
    dark/light theme, SQLite persistence + scrape cache.
- **Out (non-goals, for now)**
  - Step 8 repair-cost calculator (placeholder: manual repair estimate field).
  - Real Carfax/AutoCheck reports.
  - Auth, multi-user, hosting/deployment.
  - Bidding/automation on Copart/IAAI.
  - Live smoke tests against real sites (explicitly not chosen; see Decisions).

## Decisions

### Architecture & stack
- **Architecture:** React SPA + local Node backend — the only way to reach the sources;
  Playwright handles bot protection best from a residential IP. (Rejected: frontend-only
  — CORS/bot protection; browser extension — more fragile/work; paid APIs — cost, still
  no BG coverage; hosted serverless — datacenter IPs get blocked.)
- **Repo layout:** pnpm workspace monorepo:
  - `apps/web` — Vite + React + TypeScript
  - `apps/server` — Fastify + TypeScript
  - `packages/core` — pure shared logic (types, cost calc, matching, averaging, verdict)
    so it is unit-testable and used by both sides.
- **UI:** Tailwind CSS + shadcn/ui components + lucide-react icons; TanStack Query for
  server state; React Router for routes (Search, Tracking, Settings).
- **i18n:** i18next + react-i18next from day one, locales `en` (default) and `bg`.
  No hardcoded UI strings.
- **Runtime:** Node 26 (`.nvmrc`), pnpm 10, TypeScript 6.0 (typescript-eslint does not
  support TS 7 yet). Node 20 is EOL and too old for Vitest 5 / React Router 8. The machine's
  active nvm Node may differ — run `nvm use 26` before `pnpm`.
- **Theme:** dark default, light toggle (small own ThemeProvider). Theme + language are kept
  in localStorage for instant load and synced with the settings API in task 35.
- **Storage:** SQLite on backend via Node's built-in `node:sqlite` + Drizzle ORM
  (`sqlite-proxy` driver) — no native addon to compile (better-sqlite3 had no Node 26
  prebuild and failed to build). Migrations generated by drizzle-kit into
  `apps/server/drizzle/` (`pnpm --filter @car-porter/server db:generate`) and applied on
  startup. Tables: settings (single JSON row resolved against core defaults), lots,
  lot_inputs, tracked_lots, auction_records (bidfax matches and VIN history share one
  table), market_listings, market_price_snapshots, selections, scrape_cache. (Rejected: localStorage — fragile,
  no scrape cache; JSON files — no querying.)
- **Scraping:** **Patchright** (Playwright fork without the CDP automation leaks) driving the
  **installed Google Chrome** (`channel: 'chrome'`, so Chrome must be installed), headless, with a
  normal desktop Chrome UA passed as `--user-agent` (matching the installed version). Persistent
  browser profile per source (git-ignored). Verified 2026-09-16: stock Playwright loops on
  bidfax's Cloudflare Turnstile even when a human clicks; Patchright passes it headless with no
  interaction. No CAPTCHA solving. Approach cross-checked with the car-parts-backend crawler
  (installed Chrome, AutomationControlled off, in-page fetch, halt on block pages). Prefer intercepting the sites' own JSON/XHR responses over DOM parsing
  where available. Each source is an adapter: `fetch` (network) separated from
  `parse` (pure function over HTML/JSON) so parsers are fixture-testable.
- **Politeness:** per-source serial queue, randomized delay between page loads
  (default 1.5–4 s). Every panel has a "refresh (ignore cache)" action.
- **Caching & reuse:** calculations (cost, averages, verdict) are always recomputed
  on the fly from stored data + current settings/FX — never cached. Scraped data:
  - Lot search results: 30 min TTL. Opened lot details persisted; reopening shows stored
    data immediately (stale-while-revalidate).
  - Bidfax sold matches: **stored permanently** (sold results are immutable). Repeat
    estimates scan incrementally — newest first — and stop when an already-stored sale is
    reached; only the 12-month window is applied when averaging.
  - VIN/lot history entries: stored permanently; re-check only appends new appearances.
  - BG market listings: 24 h TTL; listings stored by URL with price snapshots (shows price
    drops / removed listings).
  - ECB FX: refreshed once per day.
  - Tracked lots: kept until removed.
  - Include/exclude choices on matches and listings are persisted per lot.
  - Each section shows "fetched X ago" + a refresh button that bypasses the cache.
- **Source errors:** each adapter returns typed errors (`blocked`, `login_required`,
  `parse_failed`, `timeout`, `not_found`); UI shows a per-source status badge, never
  fails the whole view.

### Step 1–2: Search
- Filters: make, model (dependent on make), yearFrom, yearTo. Make/model lists come from
  the free NHTSA vPIC API, cached in SQLite; each source adapter maps make/model names to
  its own identifiers.
- **Browser mode (verified 2026-09-16):** Chromium `channel: 'chromium'` (full "new headless",
  not the headless shell) + a normal desktop Chrome user agent matching the bundled version +
  `--disable-blink-features=AutomationControlled`. The default headless UA ("HeadlessChrome")
  gets blocked by Copart's Imperva protection.
- **Copart (verified live):** a long-lived page on copart.com in the persistent `copart`
  profile; searches call the site's own `POST /public/lots/search-results` from inside that page
  (`fetch` with the `XSRF-TOKEN` cookie as `x-xsrf-token`). Filters `MAKE`/`MODL`/`YEAR`, 100 per
  page. Works as a guest — **login is optional** (moved to Settings, task 35) since search needs
  none. On 403/challenge the session page is re-bootstrapped once.
- **IAAI (verified live):** guest. Page calls `POST /Search?c=<ts>` with a JSON body (keyword
  "make model" + Year range, 100 per page); response is HTML, parsed with cheerio from
  `title="Label: value"` attributes and the `ImageModalClicked(...)` args. Total = sum of the
  embedded Year facet counts. No bids for guests — ACV and Buy Now are shown instead.
- **Block detection:** strong markers (Cloudflare "Just a moment", Incapsula incident) always
  count; weak markers (`_Incapsula_Resource`, `challenge-platform` scripts) only on tiny pages,
  since real IAAI/Copart pages embed them.
- Manual live check: `pnpm --filter @car-porter/server exec tsx scripts/live-search.ts toyota camry 2018 2020`.
- Result list merged, each row: photo, source badge, year/make/model/trim, lot #, VIN
  (may be masked), odometer, primary damage, title type, location, sale date, current
  bid, Buy Now. Client-side sort + filter by source. Pagination: load pages on demand.

### Step 3: Detail panel
- Clicking a lot opens a detail panel (side sheet) with sections and **manual buttons**:
  "Estimate price", "Check history", "Check BG market". Cost calc and verdict render
  live from whatever data exists. (Rejected: auto-run everything — wastes scrapes while
  browsing.)
- **Year matching is always the clicked lot's exact year** (for bidfax and BG markets).
  The step-1 year range only filters the lot list.
- "Track" button saves the lot + all fetched results to the tracking list.

### Step 4: Bidfax price estimate
- **Source decision (2026-09-16):** bidfax only. bid.cars was considered as a second source but its
  archived (sold) results are not shown to guests, so it was dropped.
- **bidfax specifics (verified live):** exact-year listing URL
  `/{make}/{model}/f/from-year=Y/to-year=Y/[page/N/]`, newest sales first, ~10 cards per page.
  Model slugs come from the make page's links (cached 30 days). Only page numbers that the
  pagination links to are requested — guessing deep pages (e.g. 999) trips bidfax's own "429"
  anti-bot trap. Cloudflare check usually clears in ~5 s; when it sticks, the fetcher reloads (up
  to 3 × 20 s). Card text is Ukrainian or Russian; both label sets are parsed.
- Cards have no fuel field: fuel is derived only from explicit title keywords (Hybrid, Plug-in,
  Electric, Diesel/TDI), otherwise "unknown" — so hybrids don't pollute petrol averages.
- "On approval" sales (seller hadn't accepted yet) are included by default with a status badge;
  the user can untick them.
- Scan stop reasons: empty page, reached an already-stored sale (incremental), whole page older
  than the window, enough matches, page limit, last linked page. A successful scan is reused for
  24 h (per make/model/year, shared by all lots of that model/year); failed scans keep the records
  fetched so far and are not cached.
- Match rules: same make + model + **exact year** + same engine/trim/fuel.
- Limits: sold within last **12 months**, up to **20 matches**, scanning up to
  **20 pages** — stop at whichever limit is hit first. All three limits editable in
  settings.
- Output: list of matches — link (opens bidfax page directly), final price (USD), sale
  date, damage, odometer, auction — plus average. Each match has an include checkbox;
  excluding recalculates the average (damage/mileage aren't match criteria, so outliers
  are handled manually). Median shown alongside average.

### Step 5: Vehicle history
- Sources: auction-history sites — bidfax VIN/lot search first, then stat.vin (more can be
  added as adapters). Not the paid Carfax product.
- Searches by VIN and by lot number; results deduplicated by (auction, lot, date).
- **VIN paste** input in the panel overrides the lot VIN (for VINs masked in listing but
  visible in photos); basic VIN validation (17 chars, no I/O/Q, check digit warning only).

### Step 6: Landed cost
All percentages are applied to the **bid**:
```
feesRate  = 40%            (toggle "reduced": 40% / 3 ≈ 13.33%)
fees      = bid × feesRate                           [USD]
usdTotal  = bid + fees + shippingUsaRotterdam(2500)  [USD]
eurTotal  = usdTotal × usdToEur
          + rotterdamSofia (1000 €)
          + sofiaToBg (250 €, toggle, on by default)
```
- The 40% is displayed as its three parts (10% + 20% + 10%) in the breakdown.
- Bid input defaults to the **bidfax average** (editable); if no estimate has been run yet,
  falls back to Buy Now, else current bid, with a "no estimate yet" hint.
- All amounts/rates editable in settings (defaults above): 10/20/10 %, reduced divisor 3,
  2500 USD, 1000 EUR, 250 EUR.
- FX: live ECB USD→EUR reference rate (free XML feed), cached daily; manual override in
  settings. Breakdown shows the rate used and its date.
- Money handled in integer cents to avoid float errors; rounding to 2 decimals only for
  display.

### Step 7: BG market comparison
- mobile.bg and cars.bg always on; autoscout24 (BG location) and OLX.bg as toggles
  (default off).
- Match: make + model + **exact year** + trim. Optional toggles: mileage (± range, default
  ±30 000 km; lot miles converted to km), transmission, fuel (and engine where the site
  supports it).
- Results **grouped by marketplace**: each listing with link, price (EUR), year, km, fuel,
  transmission, include checkbox. Per-marketplace average + overall average of included
  listings (median shown too).

### Step 8: Repair (placeholder)
- Manual "repair estimate (€)" field per lot, default 0, included in margin. To be
  replaced by a calculator later.

### Step 9: Verdict
```
margin = bgAverage − eurTotal − repairEstimate
margin ≥ 3000 €  → Worth it (green)
0 ≤ margin < 3000 → Borderline (amber)
margin < 0       → Not worth (red)
```
- Threshold editable in settings. If BG average or bid is missing → "Insufficient data"
  state listing what's missing.

### Testing
- **Unit (Vitest):** everything in `packages/core` — cost calc (full & reduced, 250 € toggle,
  FX), averaging/median with exclusions, matching rules, year/mileage/unit conversions,
  VIN validation, verdict thresholds. Exact expected numbers.
- **Parser tests (Vitest + fixtures):** for every source adapter, real pages/JSON saved
  under `apps/server/test/fixtures/<source>/` and parsed offline; assert extracted fields.
  Include fixtures for empty results and blocked/challenge pages.
- **API tests (Vitest + Fastify inject):** routes with adapters mocked; cache and error
  mapping behavior.
- **E2E (Playwright test):** web + server with mocked adapters (fixture-backed): filter →
  list → click → each button → cost → verdict → track → settings change → i18n + theme
  switch.
- **No live smoke tests** (owner's choice). Consequence: site markup changes surface only
  at runtime — mitigated by the `parse_failed` status badges and by refreshing fixtures
  when that happens.
- **Definition of done for any task:** tests written, `pnpm test` (and `pnpm e2e` where
  relevant) pass, typecheck + lint clean, and manually verified once in the running app
  for scraper tasks. A task is not checked off otherwise.

## Testing & Acceptance
- `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm e2e` all green on the final commit.
- Unit tests prove exact cost numbers. Reference case (FX 1 USD = 0.90 €, bid 5000 $):
  - Full: fees 2000 $ → 9500 $ × 0.90 = 8550 € + 1000 € + 250 € = **9800.00 €**.
  - Reduced: fees 666.67 $ → 8166.67 $ × 0.90 = 7350.00 € + 1250 € = **8600.00 €**.
  - Without 250 €: 9550.00 € / 8350.00 €.
  - Verdict with BG average 13 000 €, repair 0: full → margin 3200 € → Worth it;
    repair 500 € → 2700 € → Borderline.
- Each scraper adapter: fixture parser tests pass **and** one manual run in the real app
  returned real data (noted in the task's commit/PR).
- E2E covers the full flow: filters → list → detail → estimate → history (with VIN paste)
  → cost toggles → market with toggles → verdict → track → settings → language/theme.

## Open Questions / Assumptions
- ~~Bidfax engine/trim/fuel availability~~ — resolved in task 21: trim + engine (liters, sometimes
  cylinders) come from the card title; fuel only from title keywords, otherwise unknown.
- ~~Copart/IAAI data access~~ — resolved in tasks 14–15 (see Step 1–2 decisions).
- **Scan depth:** 20 pages ≈ 200 sales ≈ one week of sales for a popular model/year, so the
  12-month window rarely binds; raise `bidfax.maxPages` in settings for rare trims (each page
  ≈ 3–4 s).
- **Rate of blocking:** assume a residential IP with delays + cache is enough; if a source
  keeps blocking, revisit (headed mode, slower queue, or paid API for that source).
- **History sources:** stat.vin/autoastat/poctra showed the same Cloudflare challenge in stock
  Playwright; re-test them with Patchright in task 24 before choosing. bid.cars needs an account
  for archived results.
- **Rounding of reduced fees (40%/3):** computed in cents, rounded half-up at the fee step.
